# LangGraph AI Agent Implementation Plan

## Plan Overview

- **Total phases**: 4
- **Agents involved**: devops_engineer, ml_engineer, prompt_engineer, coder, api_designer, ux_designer
- **Estimated effort**: High. Requires refactoring the existing AI microservice into a LangGraph state machine, adding a new Postgres instance for memory, and creating a rich UI rendering engine in React.

## Phase 1: Infrastructure & Safety Setup

### Objective
Provision the required infrastructure for conversation memory and guardrails.

### Agent: devops_engineer
### Parallel: No

### Files to Modify

- `docker-compose.yml` — Add `ai-db` (Postgres) and `llamaguard-service` containers. Configure networks.
- `.env.example` — Add `AI_DB_URL`, `LLAMAGUARD_URL`, and `X_INTERNAL_SECRET`.

### Implementation Details
The `ai-db` will be used for LangGraph persistence. `llamaguard-service` will host a LlamaGuard 3 model (or a lightweight API proxy if running locally). Ensure the `backend` and `ai-agent` services can reach these new containers.

### Validation
- Run `docker-compose build` and `docker-compose up -d ai-db llamaguard-service`.
- Verify connectivity from `ai-agent` container to `ai-db` via `psql` or a health check script.

### Dependencies
- Blocked by: None
- Blocks: 2, 3

## Phase 2: LangGraph Core Implementation

### Objective
Refactor the Python microservice to use LangGraph with stateful memory and hybrid guardrails.

### Agent: ml_engineer
### Parallel: Yes

### Files to Create

- `ai-agent/graph.py` — The Structured State Machine definition (Nodes, Edges, State).
- `ai-agent/prompts.py` — Hierarchical 'Strict System Prompts' and persona definitions.
- `ai-agent/guardrails.py` — Implementation of custom programmatic Pydantic validators.

### Files to Modify

- `ai-agent/requirements.txt` — Add `langgraph`, `langchain-postgres`, `langchain-openai`.
- `ai-agent/agent.py` — Replace legacy agent logic with the graph execution call.
- `ai-agent/main.py` — Update FastAPI endpoint to accept `thread_id` and pass to the graph.

### Implementation Details
Define a state machine with explicit nodes for `input_safety` (LlamaGuard), `router` (Intent classification), `tool_executor`, and `output_validator`. Use `gpt-4o-mini`. Implement `PostgresSaver` for checkpointing.

### Validation
- Run `pytest` on `ai-agent/graph.py` to verify state transitions and guardrail triggers.
- Mock the Go internal APIs to test the end-to-node logic.

### Dependencies
- Blocked by: 1
- Blocks: 4

## Phase 3: Go Backend Security & Deep Integration

### Objective
Secure the communication and provide deep access to system data for the AI agent.

### Agent: coder
### Parallel: Yes

### Files to Modify

- `internal/config/config.go` — Add `InternalSecret` and updated AI service URLs.
- `cmd/server/main.go` — Register additional internal routes for user profiles and past orders.
- `internal/handler/ai_proxy_handler.go` — Pass `UserID` and `ThreadID` to the AI microservice.
- `internal/service/ai_proxy_service.go` — Add the `X-Internal-Secret` header to all requests to/from the AI service.

### Implementation Details
Create a secure internal API group `/api/internal/v1` that requires a shared secret key. These routes should return structured JSON that matches the agent's tool requirements.

### Validation
- Run `go test ./internal/handler/...` to verify proxy logic.
- Manually test the internal routes using `curl` with the secret header.

### Dependencies
- Blocked by: 1
- Blocks: 4

## Phase 4: Frontend Rich Rendering Engine

### Objective
Enable the React frontend to render complex UI components generated by the AI agent.

### Agent: ux_designer
### Parallel: No

### Files to Create

- `frontend/src/components/ai/EventCard.jsx` — A specific component for rendering event details in chat.
- `frontend/src/components/ai/ActionButtons.jsx` — Reusable buttons for agent-suggested actions.

### Files to Modify

- `frontend/src/components/ChatWidget.jsx` — Update to parse 'component_data' from the agent response and render the appropriate AI components.

### Implementation Details
The agent response will now contain an optional `ui_components` array of objects (e.g. `{ type: 'EventCard', data: { ... } }`). The `ChatWidget` must handle this and map types to the new JSX components.

### Validation
- Run `npm run dev` and test with mock agent responses containing rich data.
- Ensure the widget still behaves correctly on small screens.

### Dependencies
- Blocked by: 2, 3
- Blocks: None
